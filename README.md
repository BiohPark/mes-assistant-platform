# MES Agent Hub

대화와 파일을 주고받는 React · TypeScript 프론트엔드 데모입니다. 에이전트의 실제 업무 로직은 연결된 assistant가 담당하며, 이 플랫폼은 내부 skill·knowledge나 업무 순서를 구현하지 않습니다.

## 실행

Node.js 22 이상에서 저장소 루트에서 실행합니다. 이전 앱은 `legacy/flowmes`에 보관되어 기본 실행·테스트에 포함되지 않습니다.

```powershell
npm ci
npm run dev
```

주소: http://127.0.0.1:5180

```powershell
npm test
npm run build
# 개발 서버가 켜진 상태에서 실행, 설치된 Microsoft Edge 사용
npm run test:browser
npm run test:browser:lifecycle
npm run test:browser:hub
```

## 기본 데이터와 설정

기본값은 가상의 접수·문서·검토 assistant 3개와 샘플 응답 모드입니다. 실제 담당자, 조직의 assistant 목록, 업무 자료, 사내 주소, 모델 매핑은 포함하지 않습니다. 사용자가 **System Owner → 에이전트 관리**에서 등록합니다. 기존 브라우저 데이터는 사용자가 등록한 데이터로 취급하며 덮어쓰지 않습니다.

API 연결 프로필에 URL과 모델을 지정한 후 에이전트에 연결합니다. 모델 적용 순서는 **대화 지정 → 에이전트 매핑 → 연결 프로필 기본값**입니다. API 키는 메모리에만 보관합니다. 실제 API 모드에서 실패하면 오류를 표시하며 샘플 응답으로 대체하지 않습니다. 브라우저 직접 연결이므로 API의 CORS 지원이 필요합니다.

## 사용 흐름

1. 에이전트 카드를 눌러 바로 대화합니다. 첫 메시지나 첨부가 저장될 때 업무가 생성됩니다.
2. 답변을 산출물로 저장하거나 파일을 업로드합니다.
3. 관련 대화에 같은 태그를 연결하면 자료함에서 서로의 원본 자료를 찾을 수 있습니다.
4. **이번 대화에 사용**을 체크한 자료만 다음 AI 요청에 포함됩니다. **★ 주 입력**으로 강조할 수 있습니다.
5. 전체 업무 칸반은 에이전트별 대화를 보여 줍니다. 업무 상태는 카드에서 따로 관리합니다.

태그는 실행 순서나 권한을 부여하지 않습니다. A–B와 B–C가 연결되어도 A가 C의 파일을 자동으로 찾지는 않습니다. 이미 선택한 파일 버전은 태그를 해제해도 유지되며 입력 선택을 별도로 해제해야 합니다. 과거 전송 기록은 보존합니다.

SR 접수 화면에서도 제목 입력 없이 대화를 시작하고 원하는 시점에 접수합니다. 담당자는 SR 상세에서 같은 태그를 가진 후속 대화를 시작할 수 있습니다. 요청자에게는 본인 접수 대화와 명시적으로 공유한 결과만 표시합니다.

## 저장과 백업

메타데이터와 원본 파일은 브라우저 IndexedDB `mes-agent-hub-v3`에 저장합니다. 이전 저장소가 있으면 백업 안내 후 복사하여 변환하고 원본은 남깁니다. 전체 백업에는 파일 원문·태그·입력 선택·출처가 포함됩니다. 백업 파일은 사용자 데이터이므로 Git 저장소에 넣지 마세요. 로컬 참고자료·스크린샷·백업은 Git에서 제외한 `.local-only/`에 보관할 수 있습니다.

직접 접근 링크는 같은 데이터를 가진 브라우저에서만 동작합니다. 역할 전환은 시연용이며 실제 인증·SSO·서버 권한·다중 PC 동기화는 구현 범위 밖입니다. 텍스트 자료는 API에 전달하며 PDF·Office·이미지는 원본 보관·다운로드를 지원합니다. 이 형식의 실제 분석에는 별도 API 어댑터가 필요합니다.

실제 사내 API 접속 및 assistant 업무 품질은 별도 환경 검증이 필요합니다. 브라우저 테스트는 가상의 데이터와 모의 API만 사용합니다.
