# MES Agent Hub

에이전트를 선택해 독립적인 업무를 진행하고, 선택한 대화와 파일을 다른 업무에 전달하는 React · TypeScript 프론트엔드 데모입니다. 저장소 루트에서 실행합니다. 이전 FlowMES는 legacy/flowmes에 보관하며 기본 실행·테스트 대상에서 제외합니다.

## 실행

Node.js 22 LTS 이상과 npm을 준비한 뒤 저장소 루트(mes-assistant-platform)에서 실행합니다.

```powershell
npm install
npm run dev
```

기본 주소: [http://127.0.0.1:5180](http://127.0.0.1:5180)

```powershell
npm test       # 업무 독립성·컨텍스트·모델·접수 관련 단위 테스트
npm run build  # TypeScript 검사 및 정적 빌드
npm run preview
```

정적 빌드 결과는 `dist/`에 생성됩니다. 직접 접근 링크는 `#/work/{업무 ID}?thread={대화 ID}` 형태입니다. 링크를 받는 브라우저에 동일한 로컬 데이터가 있어야 해당 업무를 볼 수 있습니다.

## 주요 화면

- **에이전트:** 검색·분류·상태 필터로 assistant를 찾습니다. 카드에서 해당 에이전트의 업무로 들어갑니다.
- **업무 보드:** 보드/목록을 전환하고 대기·진행 중·검토 필요·완료 상태로 업무를 관리합니다. 열은 워크플로우 단계가 아닙니다.
- **업무 공간:** 대화방, 모델, 입력 자료, 산출물, 체크리스트와 메모를 관리합니다. 팀 의견은 명시적 assistant 요청과 구분됩니다.
- **이전 작업 가져오기 / 다른 에이전트로 전달:** 메시지와 파일 버전을 선택하고 미리보기 후 컨텍스트로 저장합니다. 인계받은 업무의 상태와 대화는 독립적입니다.
- **SR 접수 / 내 요청:** 지정된 URS assistant와 대화하고 원하는 시점에 접수합니다. 담당자가 명시적으로 공유한 결과를 확인합니다.
- **에이전트 관리:** 관리자 역할에서 카드 정보·대표 이미지·접수용 지정·공통 API 연결 프로필을 편집합니다.
- **리포트:** 기간·참여자·에이전트 필터와 개선 자료 내보내기를 제공합니다. 지표가 비효율의 원인을 자동으로 확정하지 않습니다.

## 대표 시연

1. 상단 역할을 **요청자**로 변경하고 **SR 접수**에서 제목을 입력해 대화를 시작합니다.
2. 요청을 설명한 후 **지금 SR 접수**를 누릅니다. 접수번호, 대화 태그와 알림을 확인합니다.
3. **업무 담당자**로 전환해 URS 업무를 열고 메시지 또는 입력 자료를 선택합니다.
4. **다른 에이전트로 전달**에서 FDS 에이전트의 새 업무를 만들고 선택한 자료를 전달합니다.
5. FDS 업무의 컨텍스트 칩을 확인하고 다음 메시지에서 활용합니다. 원하지 않는 칩은 제거합니다.
6. 업무 연결을 해제해도 기존 인계 자료와 이력이 유지되는지 확인합니다.
7. 결과를 **요청자에게 공유**한 후 요청자 역할의 **내 요청**에서 확인합니다.

## 내부 AI 연결

1. **관리자 → 에이전트 관리 → 공통 AI 연결**에서 프로필을 만듭니다.
2. 실제 API 모드를 선택하고 기본 URL, Chat Completions 경로, 모델 ID 및 필요한 API 키를 입력합니다.
3. 에이전트에 해당 프로필과 기본 모델 또는 OpenWebUI assistant ID를 연결합니다.
4. 필요하면 개별 대화에서 모델을 재지정합니다. 적용 순서는 **대화방 → 에이전트 → 프로필**입니다.

브라우저에서 API를 직접 호출합니다. 대상 API가 해당 브라우저의 CORS 요청 및 인증 방식을 지원해야 합니다. 응답은 `choices[0].message.content`가 문자열인 Chat Completions 형식을 사용합니다. API 오류는 사용자에게 표시하며 샘플 응답으로 대체하지 않습니다. 샘플 모드는 로컬 시연용 응답입니다.

텍스트 파일은 원문을 함께 전달합니다. PDF·Office·이미지는 원본을 보관·인계·다운로드하지만 이 데모에는 해당 형식의 분석 어댑터가 없습니다. 외부 링크형 assistant는 직접 링크 열기, 컨텍스트 복사, 자료 다운로드로 이용합니다. 외부 대화 자동 수집이나 자료 자동 주입은 제공하지 않습니다.

내부망 API에 대한 실제 연결 성공, 사내 모델의 분석 품질 및 OpenWebUI에 구성된 개별 assistant의 동작은 이 저장소의 단위 테스트만으로 검증되지 않습니다. 실제 환경에서 별도 확인해야 합니다.

## 데이터와 데모 경계

| 항목 | 구현 |
|---|---|
| 메타데이터·원본 | IndexedDB `mes-agent-hub-v2`, 엔티티별 트랜잭션 |
| 이전 데이터 | `mes-agent-hub-metadata-v1` / `mes-agent-hub-files-v1`에서 한 번 복사, 원본 보존 |
| API 키 | React 메모리 상태만 사용; 새로고침하면 초기화 |
| 사용자·역할 | 탭별 sessionStorage, 브라우저 내부 시연용 전환 |
| 알림 | 앱 내부 알림함과 토스트 |
| SR 번호 | 로컬에서 생성 |
| 인계 | 원문 발췌 및 파일 버전을 보존하는 컨텍스트 묶음 |

역할별 화면과 변경 제한은 데모 동작이며 실제 보안 경계가 아닙니다. 서버, SSO, 권한 강제, 여러 PC 간 동기화, 이메일 알림, 실제 SR 시스템 연동은 포함하지 않습니다. GMP 운영 시스템 검증 또는 전자서명·감사 추적 규정 준수를 인증하는 제품도 아닙니다.

원본 변경·업무 보관·인계 연결 해제가 이미 받은 묶음을 수정하지 않습니다. 활성 컨텍스트를 제거하면 다음 API 요청에서 그 원문을 다시 첨부하지 않습니다. 과거 대화의 답변과 전송 기록은 보존되므로, 완전히 새로운 맥락으로 시작하려면 새 대화방을 생성합니다.

브라우저 데이터를 지우면 업무와 파일도 지워집니다. 업무 결과 묶음 JSON에는 선택 업무의 원본 파일을 base64로 포함합니다. 활성 컨텍스트뿐 아니라 연결 해제된 인계, 과거 전송 컨텍스트, 파일의 이전 버전, 대화 전송 기록과 활동 이력도 보존합니다. 원본 파일이 누락되면 내보내기를 중단하고 오류를 표시합니다. `files[]`의 `base64` 값을 디코딩하여 해당 `name`으로 저장하면 파일을 꺼낼 수 있습니다. 업무 결과 묶음은 검토·개선 자료용입니다. 전체 복원에는 관리자 화면의 **전체 데이터 백업·복원**에서 만든 별도 백업을 사용하세요. 리포트 JSON은 지표와 메타데이터용이며 바이너리 파일을 포함하지 않습니다. 같은 서버 주소와 브라우저 프로필에서 이용해야 저장한 자료가 복원됩니다.

## 코드 구조

```text
src/
  types.ts           데이터 계약
  domain.ts          상태 변경·접수·인계 규칙
  seed.ts            시연 데이터
  store.tsx          탭 세션·비동기 명령·DB 구독
  db/                트랜잭션·이관·검증·전체 백업/복원
  app/requestService.ts  요청 스냅샷·잠금·취소·중단 복구
  files.ts           IndexedDB 원본 파일 저장·다운로드
  export.ts          파일 원문·버전·인계 이력을 포함하는 결과 묶음
  api.ts             Chat Completions 요청 및 활성 컨텍스트 조립
  Gallery.tsx        에이전트 갤러리
  AgentAdmin.tsx     에이전트·AI 연결 설정
  WorkBoard.tsx      에이전트별 업무 보드
  Workspace.tsx      대화·자료·업무 상세
  ContextPicker.tsx  검색·선택·검토·인계
  App.tsx            탐색·SR·알림·리포트
```

검증 범위와 결과는 테스트 실행 출력으로 확인합니다. 브라우저 UI 검증 결과가 모든 사내 환경에서의 동작을 보장하지는 않습니다.

## 1차 안정화

- 탭 간 변경을 Dexie liveQuery로 반영하고, 같은 레코드의 오래된 편집은 충돌로 알립니다.
- AI 호출 전 사용자 메시지와 요청 원문을 저장합니다. 대화별 1개 요청, 30초 lease/10초 갱신, 취소·실패·중단 기록 및 수동 재시도를 지원합니다. 브라우저에서 취소해도 서버의 작업 중단은 보장하지 않습니다.
- 입력 자료는 대화에서 선택합니다. 기본 요청 한도는 256KiB이며 프로필에서 조정합니다. 토큰 한도와 다릅니다.
- 완료한 업무는 자료·체크리스트·본문·AI 호출을 잠그고, 사유 있는 재개 후 변경합니다. 후속 메모·공유·인계·보관은 가능합니다.
- 완료 당시 스냅샷과 개별 메시지 전송 기록을 내려받을 수 있습니다.
- 전체 백업은 원본 바이트와 SHA-256을 포함합니다. 복원은 스키마·참조·해시 검사 후 전체 교체하며 진행 중 요청이 있으면 차단합니다. 데모 복원 한도는 100MB입니다. API 키·세션·활성 잠금은 복원하지 않습니다.
- 컨텍스트 AI 요약은 원본 업무의 별도 요약 대화에, 시스템 초안 호출은 보관된 초안 업무에 기록합니다.

### 브라우저 회귀 테스트

개발 서버 실행 후 Microsoft Edge가 설치된 환경에서 npm run test:browser를 실행하세요. 별도 테스트 브라우저 저장소를 사용합니다. 두 탭 저장, 느린 모의 API, 컨텍스트 제거, 오류·재시도·중지, 역할별 공개 범위와 백업 다운로드를 확인합니다. 내부망 실제 API 연결 검증은 별도입니다.

2차(스트리밍·컨텍스트 라이브러리)와 3차(리포트·시스템 assistant 확장)는 후속 범위입니다.
