# FlowMES — MES Assistant Workspace

삼성바이오로직스 MES 그룹의 Syncade ET 개발 과정을 구체화한 **프론트엔드 전용 데모**입니다. 기존 대화형 assistant 내부 로직은 유지하고 업무·단계·세션·자료 인계를 연결하는 제품 구조를 제안합니다.

## 실행

Node.js 22.12 이상을 사용합니다.

```powershell
cd D:\_Repositories\mes-assistant-platform
npm ci
npm run dev -- --port 5173 --strictPort
```

브라우저에서 http://127.0.0.1:5173 을 엽니다. 같은 PC의 다른 브라우저나 다른 포트는 별도의 저장 공간을 사용합니다. 개발 서버를 외부에 공개하지 않고 로컬에서 실행합니다.

```powershell
npm test
npm run build
npm run preview -- --port 4173
```

빌드 결과는 `dist/`입니다. 정적 웹 서버에서 제공할 수 있습니다. 한글·영문 폰트와 아이콘을 로컬 번들에 포함하므로 실행 중 외부 CDN 요청이 필요하지 않습니다.

## 권장 시연 순서 (5–10분)

1. **워크스페이스**: 전체/내 업무, 상태 필터, 검색, 단계·담당자 필터와 목록/보드를 전환합니다.
2. **설비 상태 전이 로직 개선**: FDS 단계의 기존 대화와 URS 입력 자료를 확인합니다. 각 파일을 클릭하면 텍스트/이미지 미리보기와 다운로드가 가능합니다.
3. **대화 이어가기**: 예외 승인 조건 등을 요청합니다. 샘플 응답의 ‘산출물로 저장’을 눌러 검토 초안을 만듭니다.
4. **다음 단계로**: 미완료 체크가 있으면 이동이 차단됩니다. 체크리스트를 확인한 후 전달할 산출물만 선택합니다.
5. **수동 개발**: 회색 단계에서 작업 메모와 증빙 파일을 남깁니다. 파일은 끌어놓기 또는 파일 선택으로 추가할 수 있습니다.
6. **단계 관리**: 사유를 남기고 건너뛰거나 이전 단계로 되돌립니다. 기존 대화/파일은 유지되고 후속 작업은 재검토로 표시됩니다.
7. **워크플로우 편집**: 단계 추가, 이름/assistant 수정, 수동/assistant 전환, 순서 이동을 시연합니다. 작업 기록이 있는 단계는 삭제가 제한됩니다.
8. **보관함·활동 이력**: 자료의 원본 업무/단계와 소비 단계, 담당자별 변경 기록을 확인합니다.
9. **리포트**: 일별/주별·담당자·워크플로우 필터를 바꾸고 CSV, assistant 개선 자료 JSON을 다운로드합니다.
10. **시스템 assistant**: 새 업무를 설명하고 제안된 워크플로우를 검토한 뒤 적용합니다. 새 업무는 일반 생성 폼에서도 만들 수 있습니다.

## 구현된 범위

| 요구사항               | 구현                                                               |
| ---------------------- | ------------------------------------------------------------------ |
| assistant 간 자료 전달 | 산출물 ID/버전을 보존하는 선택적 입력 연결                         |
| 업로드/다운로드        | IndexedDB Blob 저장, 파일당 25MB, 다운로드, 텍스트·이미지 미리보기 |
| 단계별 대화·세션 재개  | 단계별 메시지, 작성자·시간, hash URL 직접 접근                     |
| 진행 현황              | 업무 목록/보드, 단계 시각화, 진행률, 상태 필터                     |
| 수동 업무              | 회색 단계, 메모, 첨부, 체크리스트                                  |
| 유연한 워크플로우      | 템플릿 생성/복제/편집, 업무별 단계 추가·재정렬·역할 변경           |
| 진행 제어              | 체크리스트 게이트, 사유를 요구하는 되돌리기/건너뛰기               |
| 추적                   | 대화·메모 작성자, 자료 출처와 버전, 단계 전환·편집 활동 이력       |
| 외부 시스템 연결       | 현재 단계 링크 복사 + 설정 가능한 외부 URL 템플릿                  |
| 리포트                 | 기간·담당자·워크플로우 필터, 활동·완료·재검토 지표, CSV/JSON       |
| 시스템 assistant       | 키워드 기반 워크플로우 제안과 확인 후 업무 생성                    |

## 데모와 운영 시스템의 경계

- LLM 응답과 제안은 **정해진 샘플 로직**입니다. OpenWebUI/GLM-5.2 또는 사내 모델을 실제 호출하지 않습니다. 첨부 문서의 의미 분석도 수행하지 않습니다.
- 메타데이터는 localStorage, 업로드 원문은 IndexedDB에 저장합니다. **한 브라우저 탭에서 시연**하는 용도입니다. 동시 사용자/동시 탭 병합·서버 저장·권한 통제는 구현하지 않았습니다.
- 브라우저 데이터를 지우면 해당 브라우저의 작업과 업로드 파일이 사라집니다. 초기 샘플을 다시 보려면 다른 브라우저 프로필/다른 로컬 포트에서 실행할 수 있습니다.
- 완료 단계의 체크리스트는 읽기 전용입니다. 사유를 남겨 단계를 되돌린 후 수정합니다. 모든 이전 단계가 완료/건너뜀 상태여야 마지막 단계를 마무리할 수 있습니다.
- 문서 미리보기는 텍스트·Markdown·CSV·JSON·이미지를 지원합니다. DOCX, XLSX, PDF 등은 업로드/전달/다운로드로 취급하며 전용 프로그램으로 확인합니다.
- 개선 자료 JSON에는 대화·체크리스트·메모·이력·파일 메타데이터가 포함됩니다. 업로드 원문은 보관함에서 별도 다운로드합니다. assistant skill을 자동 수정하지 않습니다.
- 외부 시스템 주소는 설정에서 `https://internal.example/tasks/{id}` 형태로 입력합니다. 실제 URL은 조직에서 제공해야 합니다. 브라우저 hash 링크를 외부 시스템에 등록하면 이 업무/단계로 돌아올 수 있습니다.
- 실제 DB 조회, 배포, GMP 승인·전자서명·검증된 감사증적을 구현한 시스템은 아닙니다.

## 구조

```text
src/
  App.tsx          앱 셸, 업무 목록, 새 업무, 설정, 시스템 assistant
  Workspace.tsx    단계별 작업 공간, 대화, 수동 메모, 자료 인계
  Pages.tsx        워크플로우 편집, 보관함, 활동 이력, 리포트
  domain.ts        순수 상태 전환, 안전한 구조 병합, 업무 생성
  domain.test.ts   상태 전환과 작업 보존 회귀 테스트
  store.tsx        상태/브라우저 저장/파일 업로드
  storage.ts       IndexedDB, 다운로드, CSV 처리
  types.ts         도메인 타입
  seed.ts          시연 업무·대화·자료
  ui.tsx           공통 UI, 파일 미리보기, 모달
  styles.css       데스크톱/모바일 반응형 디자인
docs/
  design.md        제품 구조, 데이터 모델, 사내 연동 설계
  validation.md    검증 결과와 한계
```

## 실제 연동의 다음 단계

1. 단계별 입력/출력 템플릿과 역할·승인 책임을 확정합니다.
2. 설치된 OpenWebUI 버전에 맞춰 assistant ID, 세션 ID, 파일 업로드/knowledge 주입, 응답 스트림 어댑터를 검증합니다. OpenAI compatible 텍스트 호출이 OpenWebUI skill 실행까지 보장하지는 않습니다.
3. 사내 인증, 객체 저장소/문서 버전, 서버 이력, 동시 편집과 외부 업무 매핑을 추가합니다.
4. 모델의 단계 완료 판단은 제안으로 처리하고, 최종 단계 전환은 담당자가 확정합니다.

세부 내용은 [설계 문서](docs/design.md)에 정리했습니다.
