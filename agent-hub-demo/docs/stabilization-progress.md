# 1차 안정화 실행 기록

- 브랜치: `codex/mes-agent-hub-demo` (사용자 요청에 따라 기존 분리 브랜치 유지)
- 기준선: `2593f33`
- 범위: 반영 계획 Task 1–4. Task 5–8은 후속 범위.
- 기존 상위 데모와 비교 저장소는 수정하지 않음.

## 구현 결과

1. CommandContext로 작성자·역할·탭·명령 ID를 전달. 비동기 저장 결과를 확인하고 실패 시 입력 초안을 유지.
2. Dexie 엔티티 테이블, 최신 데이터 기반 트랜잭션, 변경 행만 저장, revision 충돌 검사, SHA-256 명령 영수증. Blob과 메타데이터 원자 저장. v1 원본 보존 및 일회성 이관.
3. 전송 전 사용자 메시지·RequestRecord 기록. 선택 자료 및 모델 스냅샷, 텍스트 조각 공유 저장, 256KiB 기본 제한. 대화별 요청 잠금, 중지/실패/중단/재시도와 역할 전환 취소. 메시지 순서 보존 및 기록 열람 정책.
4. 완료 스냅샷·구조화된 전환 이벤트, 완료 업무 수정 제한 및 사유 있는 재개. 전체 백업/복원, 해시·참조·형식 검증, 실행 요청 차단, 원자 교체 및 이전 탭 epoch 무효화.

## 실행 판단

- 기존 checkout/브랜치 사용: 사용자의 명시적 요청을 따름.
- 순수 reducer를 기존 정책 구현으로 유지. DB 명령 경계가 최신 데이터에 적용하며 UI는 집계 조회 구독을 사용. 엔티티별 화면 구독 최적화는 후속 과제이며 동시 저장 정확성과는 분리됨.
- Task 1–4는 비동기 UI·저장소·요청 수명주기 의존성으로 하나의 안정화 커밋으로 묶음. 기준선은 별도 커밋으로 보존.
- 완전한 화면 재배치는 하지 않음. 필요한 모듈부터 추출하고 기존 api.ts의 순수 request builder를 재사용.
- 업무 설정은 입력 중 DB 저장 대신 로컬 초안 + 명시적 저장으로 전환. 충돌 시 초안 유지와 최신 설정 다시 읽기 제공.
- 기존 AI 요약과 시스템 초안도 RequestService로 통합. 요약은 별도 대화, 시스템 초안은 보관 업무에 기록. 완료 업무의 AI 요약은 재개 후 가능하며 수동 요약 인계는 유지.
- 브라우저의 중지는 서버 작업 중단/정확히 한 번 실행을 보장하지 않음.
- 내장 CUA 도구는 Transport closed로 사용 불가. 격리된 실제 Microsoft Edge를 Playwright로 실행해 검증.

## 검증

- 실패를 먼저 확인: CommandContext, 저장 계층, RequestService, 완료 정책, 백업, 대화 순서·손상 백업, 업무 설정 저장.
- 단위/통합 테스트: 37개. 동시 append·충돌·이관 재진입·Blob 누락/용량 오류 롤백·요청 잠금/취소/만료·중단 복원·공개 범위·해시·완료 기록 포함.
- 브라우저: `npm run test:browser` — 두 탭 append, 탭 역할 격리, 업무 설정 저장, 느린 모의 API, 전송 중 칩 제거, 모델, API 오류/재시도/중지, 요청자 비공개, 새로고침, 백업 다운로드.
- 빌드: TypeScript + Vite.
- 독립 리뷰: 6개 발견 사항을 수정. 메시지 순서, 완료 백업 내부 구조, Blob 해시, 프로필별 키 선택, 요약/초안 수명주기, 요청자 기록 접근. 수정 후 해당 6개 항목에 남은 blocker 없음 확인.
- 사내 실제 API, 여러 PC 동기화, 운영 인증은 검증/구현 범위 밖.
