# FlowMES — MES assistant workflow platform

## 제품 방향

MES 담당자가 업무 맥락을 유지하면서 기존 대화형 assistant를 사용하는 실행 공간. 외부 업무관리 시스템을 원장으로 유지하고 여기서는 단계, 파일 전달, 세션, 체크리스트와 실행 이력에 집중한다. 초기 기본 페르소나는 MES 개발 담당자이며 URS 단계에 비즈니스오너가 참여할 수 있다.

## 검토한 구성

1. **업무 허브 + 단계별 작업 공간 (선택)**: 전체 업무와 실제 대화를 분리하고 산출물 계보를 연결. 가장 중요한 파일 전달과 세션 재개에 적합.
2. 채팅 단일 화면: 학습은 쉽지만 여러 단계와 입력/출력 버전 구분이 어렵다.
3. 칸반 중심: 상태 확인은 쉽지만 단계 간 문서 선택과 긴 대화에 추가 이동이 필요하다.

## 정보 구조와 데모 범위

- 업무 목록: 검색, 내 업무, 상태/현재 단계 필터, 목록/보드, 신규 업무.
- 작업 공간: 가로 단계 흐름, 단계별 대화/수동 메모, 입력 자료/산출물, 체크리스트, 이력. URL hash로 업무·단계 직접 접근.
- 인계: 원본 산출물 ID를 다음 단계 입력에 연결. 사용자가 인계 목록을 선택하며 원본 삭제나 복사를 자동으로 수행하지 않는다. 추가 첨부와 입력 연결 해제 지원.
- 워크플로우: 기본 URS → FDS → 개발(수동) → 테스트 → GMP 검증 → 배포 검증(수동). 단계 추가, 이름/assistant 변경, 순서 변경, 삭제는 구조 편집으로 수행. 진행 중이거나 작업 기록이 있는 단계는 삭제하지 못한다.
- 전환: 체크리스트 완료 뒤 다음 단계로 이동. 건너뛰기·되돌리기는 사유 필수이며 이력에 남긴다. 이미 완료된 후속 단계는 재검토 상태로 변경하고 기존 세션/자료는 보존한다.
- 문서함: 전체 파일 검색, 업로드, 텍스트/이미지 미리보기, 다운로드. 파일 본문은 IndexedDB, 업무 메타데이터는 localStorage에 저장.
- 리포트: 일별/주별, 담당자/워크플로우 필터, 상태 분포와 재작업/정체 분석, CSV와 assistant 개선 자료 JSON 다운로드.
- 시스템 assistant: 키워드에 따른 샘플 대화와 검토 가능한 워크플로우 제안. 사용자가 적용하면 신규 업무 생성.
- 개인 설정: 표시 이름과 외부 업무시스템 URL 템플릿 저장. 사내 모델 연결은 설정 가이드만 제공한다.

## 데이터 모델

WorkItem(id, title, system, owner, priority, due, externalId, stages[])
Stage(id, name, short, mode, assistant, status, inputs[], outputs[], checklist[], messages[], notes[])
Artifact(id, name, mime, size, version, sourceWorkId, sourceStageId, createdBy, createdAt)
AuditEvent(id, workId, stageId, actor, action, detail, timestamp)
Template(id, name, description, stages[])
메시지/메모/체크는 stage ID에 귀속된다. 단계 재정렬과 세션 재개에도 연결이 유지된다.

## 사내 연동 확장 설계

UI → 업무 서비스 → OpenWebUI adapter → 기존 대화형 assistant. assistant 내부 skill/knowledge 워크플로우는 변경하지 않는다. UI와 어댑터 사이에는 세션 ID, 모델/assistant ID, role/content 메시지, 첨부 파일 참조, 응답 스트림 계약을 둔다. 실제 OpenWebUI 파일 업로드·지식 연결·모델 선택 API는 설치 버전에 맞춰 검증한다. OpenAI compatible 텍스트 메시지 지원이 문서 처리나 OpenWebUI skill 실행까지 보장하지는 않는다.

업무 서비스는 권한 확인 후 선택된 입력 자료를 업로드하고 어댑터의 파일 ID와 원본/버전을 매핑한다. assistant 응답을 받은 뒤 사용자가 산출물로 확정하고 다음 단계에 전달한다. 완료 추정은 제안까지만, 단계 전환은 사용자 판단이다. 배포는 외부에서 수동 수행하고 그 증빙과 DB 조회 결과를 입력한다.

## 실제 운영 전 필요한 구성

사내 SSO/RBAC, 서버 저장소와 파일 검사, 버전 불변성/파일 해시, 서버 기준 변경 이력, 세션 동시 편집 제어, retention/backup, 외부 시스템 양방향 매핑, OpenWebUI 인증/스트리밍/취소/재시도, 검증된 read-only DB adapter가 후속 구현 대상이다. 브라우저 저장과 화면상의 이력은 운영용 감사증적이 아니다. GMP 관련 승인은 조직의 검증 절차에 맞춰 별도 설계하며 데모는 검증/전자서명/규정 적합성을 주장하지 않는다.

## 실패 처리와 검증

파일 저장 실패는 사용자에게 표시하고 성공 메타데이터를 남기지 않는다. 저장 용량 부족은 배너로 표시한다. 모델은 연결하지 않고 모든 응답을 샘플로 명시한다. 체크리스트 게이트, 선택적 인계, 사유 검증, 후속 단계 재검토, 세션 보존은 단위 테스트로 검증하고 실제 브라우저에서 목록/대화/파일/편집/리포트/새로고침을 점검한다.
